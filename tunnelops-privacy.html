TunnelOps 隱私權政策

01

適用範圍與資料控制者

本政策適用於 CB Studio 提供的 TunnelOps 道路隧道路況 App（以下稱「本 App」）及其支援聯絡。 本 App 用於呈現道路隧道目錄、來源狀態與可用的即時／近期路況，不是導航、緊急通報或駕駛輔助系統。

資料控制與政策聯絡人為 CB Studio。您可透過 aa22396584@gmail.com 與我們聯絡。

02

本 App 實際處理哪些資料

資料類型 何時處理 用途與去向
固定隧道識別碼、方向與筆數上限 載入路況或隧道詳情時 傳送至 Google Firebase Functions，由 CB Studio 的後端程式處理，以取得相對應的公開道路路況與隧道資料。
您輸入的搜尋文字與選用的國家代碼 您使用隧道搜尋時 傳送至 Google Firebase Functions，由 CB Studio 的後端程式完成目錄查詢。我們不把它寫入搜尋歷史或開發者使用者檔案；請勿在搜尋欄輸入個人資料。
Firebase 函式名稱、呼叫端 IP 位址與 FCM token 每次呼叫 Firebase callable function 時 Cloud Functions 用戶端 SDK／服務會自動將這些資料提供給 Google Firebase，用於定位與執行函式、回傳結果、安全及防濫用。Firebase 官方說明指出，即使 App 未包含或使用 Firebase Cloud Messaging SDK，Functions 仍會收集 FCM token；TunnelOps 目前不發送通知，也不在 CB Studio 後端使用或儲存該 token。
Firebase Installation ID（FID）與 Firebase user-agent 裝置中繼資料 Firebase 相依元件初始化或連線時 目前 Android dependency graph 會帶入 Firebase Installations；其產生並傳送每次安裝的 FID（不等同於唯一使用者或實體裝置識別碼）。Google Firebase 亦可能收到作業系統版本、名稱、型號、品牌、裝置類型、安裝來源，以及 Firebase SDK 名稱／版本，用於識別 App 安裝並提供、維護及改善 Firebase。TunnelOps 不把 FID 對應到帳戶或開發者使用者檔案。
App／裝置完整性訊號、App Check token 與 Play Integrity token staging 或 production App 啟動及呼叫 Firebase 服務時 傳送至 Firebase App Check 與 Android release 使用的 Google Play Integrity；若發行 Apple release，則也由 Apple App Attest 處理。用途是驗證 App 執行環境、保護後端與防止濫用。主要 callable 的 enforcement 可能分階段啟用。
公開路況快照、來源健康狀態、時間與快取版本 Android 成功取得有效路況後 儲存於 App 私有的 Android SharedPreferences，供短暫離線／弱網顯示。內容是道路資料，不是您的行蹤。
支援信件內容與寄件地址 只有當您主動寄信給我們 用於回覆問題、調查錯誤與保存必要的支援紀錄；這發生在您的郵件服務中，不是 App 內背景蒐集。

目前版本不要求或未整合

  • 使用者帳戶、登入憑證、聯絡人、照片、麥克風、相機或精確／背景位置。
  • Firebase Analytics、Firebase Crashlytics、廣告 SDK、廣告識別碼、訂閱或 App 內購買。
  • 背景位置追蹤、個人化警示、行車路線或使用者產生內容的雲端同步。
03

本機快取、保存與刪除

Android 版會將通過驗證的路況 feed 儲存在 App 私有空間。App 以來源最舊觀測時間為基準，超過兩小時的資料不再符合顯示資格； 無效、環境不符或過期資料會在下次驗證時清除。因此，快取檔可能在尚未再次開啟／驗證前留在裝置上，但不會被重新整理時間延長為「有效即時資料」。

您可透過 Android「設定 → 應用程式 → TunnelOps → 儲存空間 → 清除儲存空間」，或解除安裝本 App，刪除本機資料。 Android 是否將 App 資料納入裝置備份，取決於作業系統、Google 帳戶與您的備份設定。

我們的後端保存道路路況快照、來源健康與庫存發布資料；這些不是使用者帳戶資料。 CB Studio 的 callable 程式會使用查詢內容處理當次請求，但不會把搜尋文字、國家代碼、固定隧道識別碼、呼叫端 IP、FCM token、FID、Firebase user-agent 中繼資料或完整性 token 寫入開發者管理的使用者檔案或應用程式資料表。

這不表示所有網路處理都是即時拋棄。Firebase／Google 可能依其服務設定、資安需求、法令與保存政策保留請求、安全或營運紀錄，且可能使用協助提供 Firebase 的服務分包商。 CB Studio 不控制 Google 各類技術紀錄的確切保存期，也通常無法在沒有帳戶對應資訊的情況下，從該等紀錄辨識並刪除特定使用者的單筆資料。 支援郵件只在處理問題、法律義務或防止濫用所需期間內保留；您可來信要求刪除您提供的支援內容，但依法或為資安所需者可能須繼續保存。

清除 App 儲存空間或解除安裝會移除裝置上的 TunnelOps 快取與本機 SDK 資料，但不保證同步刪除 Firebase／Google 已產生的技術或安全紀錄；重新安裝或再次初始化 Firebase 可能產生新的 FID 或 token。

05

安全、跨境處理與您的選擇

Firebase 對上述資料使用 HTTPS 加密傳輸；Android 快取使用 App 私有儲存空間。我們採取與資料性質相稱的措施，但任何網路或裝置儲存均無法保證絕對安全。 Google，以及 Apple release 如發行時的 Apple，可能在您所在地以外的資料中心處理技術資料，並依其契約與隱私政策提供保護。

  • 停止網路處理：您可停止使用或解除安裝本 App；主要功能需要網路才能取得新資料。
  • 刪除本機資料：使用 Android 系統的清除儲存空間功能或解除安裝。
  • 支援資料請求：您可來信要求查詢或刪除您主動提供給我們的支援信件；我們可能需要確認來信地址。

本 App 目前不建立使用者帳戶、Firebase Authentication user ID 或 CB Studio 使用者檔案。FID、FCM token 與完整性 token 是技術識別／安全資料，不是 TunnelOps 帳戶；我們通常無法把 Firebase 基礎設施紀錄與可操作的帳戶關聯，也不會假裝提供不存在的「刪除帳戶」按鈕。

06

本 App 是一般道路資訊工具，並非專為兒童設計。我們不透過帳戶或廣告功能故意蒐集兒童個人資料。 若您認為兒童曾透過支援郵件提供個人資料，請聯絡我們處理。

03

Local cache, retention, and deletion

Android stores a validated traffic feed in app-private storage. Data older than two hours from the oldest source observation is never display-eligible. Invalid, environment-mismatched, or expired entries are cleared when next validated. A cache file can therefore remain on the device until the next validation or manual clearing, but a refresh timestamp cannot make old source data “live” again.

Delete local data through Android Settings → Apps → TunnelOps → Storage → Clear storage, or uninstall the App. Whether Android includes app data in a device backup depends on the operating system, Google account, and your backup settings.

Our backend retains road-traffic snapshots, source-health records, and inventory release data; these are not user-account records. CB Studio callable code uses query content to handle the request but does not write search text, country codes, fixed tunnel identifiers, caller IP addresses, FCM tokens, FIDs, Firebase user-agent metadata, or integrity tokens to developer-managed user profiles or application tables.

This does not mean all network processing is immediately discarded. Firebase/Google may retain request, security, or operational logs under its service settings, security needs, legal requirements, and retention policies, and may use subprocessors that help provide Firebase. CB Studio does not control the exact retention period for each category of Google technical log and generally cannot identify and delete an individual user's entry without account-linked information. Support mail is retained only as needed to resolve an issue, meet legal obligations, or prevent abuse. You may ask us to delete support content you provided, although legal or security needs may require continued retention.

Clearing App storage or uninstalling removes TunnelOps cache and local SDK data from the device, but does not guarantee deletion of technical or security logs already generated by Firebase/Google. Reinstallation or Firebase reinitialization may create a new FID or token.

05

Security, international processing, and your choices

Firebase encrypts the data described above in transit using HTTPS, and the Android cache uses app-private storage. We use measures appropriate to the limited data involved, but no network or device storage is absolutely secure. Google—and Apple if an Apple release build is distributed—may process technical data in data centers outside your location subject to their contracts and privacy terms.

  • Stop network processing: stop using or uninstall the App. New traffic information requires network access.
  • Delete local data: use Android’s clear-storage control or uninstall the App.
  • Support-data request: email us to ask about or delete support correspondence you provided. We may need to verify the sending address.

The current App creates no user account, Firebase Authentication user ID, or CB Studio user profile. FIDs, FCM tokens, and integrity tokens are technical identifiers or security data, not TunnelOps accounts. We generally cannot associate Firebase infrastructure logs with an actionable account, and we do not present a fictional “delete account” control.
